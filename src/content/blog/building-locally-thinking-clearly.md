The best tools disappear into the work. They shorten the distance between an idea and the first honest version of it.

I am interested in local-first creative systems because they make that distance smaller. A model on your own machine can be available when the network is not, keep unfinished ideas close, and turn experimentation into an ordinary habit rather than an event.

## Start with the smallest useful loop

My preferred loop is simple:

1. Write down the question in plain language.
2. Build the smallest version that can answer it.
3. Use it long enough to notice what is awkward.
4. Improve only the part that gets in the way.

This is slower than chasing every new tool and faster than maintaining a complicated system you do not use.

## Local does not mean isolated

Local tools are most useful when they work well with the wider web. Code can begin privately, move to GitHub when it is ready, and publish through a simple static site. The boundary should be a choice, not a limitation.

## Make the work legible

A good workflow leaves a trail: short notes, clear commits, and small decisions that can be understood later. That trail matters as much as the final artifact. It makes collaboration with people—and with AI—more reliable.

This blog is where I will share those experiments: what worked, what did not, and what I learned while building.
